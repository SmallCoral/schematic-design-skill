# schematic-design

一套给 AI Agent 用的硬件原理图设计规则，适合画芯片最小系统、电源、接口和传感器电路，也能用来修改、检查已有原理图。

画图时容易漏掉的东西，往往藏在小地方。导线看着挨到了引脚，实际没有接上；网络名写得一样，作用域却不一样；封装名称很接近，引脚顺序又对不上。这套 Skill 把这些问题连同分页、选型和交付检查写进了设计要求。完整规则放在 [SKILL.md](https://github.com/SmallCoral/schematic-design-skill/blob/main/SKILL.md)，使用前可以直接翻看。

工作范围到原理图为止，包括必要的符号库，以及封装、3D 模型的引用和绑定。它不会继续做 PCB 布局布线，也不生成 Gerber 等制板文件。

## 先说使用条件

仓库目前包含 `SKILL.md` 和 `agents/openai.yaml`，没有附带自动绘图脚本、EDA 软件或元件库。Skill 负责告诉 Agent 怎样做事，实际画图仍要依靠你已经准备好的工具。

使用时需要一个能读取 Agent Skills 的环境，以及可用的原理图编辑能力。编辑能力可以来自 EDA 接口、自动化工具，或能可靠修改目标文件格式的程序。还需要让 Agent 能读取项目、元件库和相关原厂资料。

已有项目会沿用原来的 EDA 软件、文件格式和库。新项目没有指定软件时，先整理需求和电路方案，等文件格式会影响交付时再确认。规则不绑定某一家 EDA，也没有在仓库里提供各家软件的连接器。

只有对话能力时，可以讨论方案和检查材料；要交付可编辑原理图，必须有对应的编辑工具。缺少视觉检查或 ERC 能力时，交付说明里也要留下这一项，不能把没检查过的地方写成通过。

## 放到哪里

以 Codex 的项目级安装为例，在你的项目根目录执行下面这条命令。需要先安装 Git，目标目录应当尚不存在。

```sh
git clone https://github.com/SmallCoral/schematic-design-skill.git .agents/skills/schematic-design
```

不使用 Git 也可以下载仓库，把整个目录放到同一个位置。确认文件位于 `.agents/skills/schematic-design/SKILL.md`，并保留 `agents/` 目录。

想让它对多个项目可用，可以放在用户目录的 `.agents/skills/schematic-design/` 下。Windows 对应 `%USERPROFILE%\.agents\skills\schematic-design\`，macOS 和 Linux 对应 `~/.agents/skills/schematic-design/`。这些发现位置来自 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。Codex 会自动发现新增技能，未出现时再重启。

Skill 的名称是 `schematic-design`，显示名称是「硬件原理图设计」。在 Codex CLI 或 IDE 扩展里，可以用 `$schematic-design` 明确指定它；其他支持 Agent Skills 的工具，请按各自的加载方式安装。

## 怎么开始一项设计

把电源条件、接口电平和主要器件约束一起告诉 Agent。已经选定芯片时，最好给出完整订货型号和封装版本；已有图纸时，直接提供项目路径。预算、尺寸和器件偏好会影响选型，有要求就提前写上。

下面是一条新建设计的请求示例，具体型号和参数需要按你的项目补齐。

```text
请使用 schematic-design 设计一张 MCU 与 I²C 传感器的原理图。
供电输入为 5V，MCU 和传感器工作在 3.3V，目标 EDA 为 KiCad。
先确认器件型号、电源负载和接口条件，再查原厂数据手册。
交付可编辑原理图和必要的项目库，列出 ERC 结果及未验证内容。
只处理原理图，不创建或修改 PCB。
```

修改已有图纸时，可以这样说。

```text
请使用 schematic-design 检查这个项目的原理图。
沿用现有器件和元件库，重点核对供电、接口电平与引脚连接。
发现问题后先说明依据，再修改相关电路；整理图纸时保持原有网络关系。
交付修改后的原理图，说明改了哪里、检查了哪些部分，以及还缺哪些资源。
不要打开或修改 PCB 文件。
```

当前任务中明确给出的参数和偏好，优先于 Skill 的默认规则。比如指定某款新芯片做实验，或指定另一种阻容封装，都可以直接说明。默认的常用低成本选型建议只适用于没有另行指定的情况。

## 图纸会按哪些规则处理

分页按真实功能决定。三个以内的模块，能清晰放进一页就优先单页；超过三个模块必须分页，并设置带电气接口的模块框图主页。少量模块但电路复杂时也可以分页，需要说明原因。一个芯片周围的去耦、复位和时钟归在同一模块里，不为了凑页数把它们拆开。

模块内部尽量用短的电气导线连接，让芯片与外围电路的关系直接可见。模块之间优先通过明确的网络名、端口或层次接口相连，并检查标签作用域。普通图形线不能充当电气导线，视觉上靠近也不能算连接完成。

选型会先看电气需求，再考虑常见程度、供应和价格。关键电路要查对应完整料号的原厂手册、推荐应用电路和勘误，留下资料链接及章节、图号或页码。调整推荐取值时，需要保留计算或资料依据。价格和库存没有实际查询结果时，不写确定结论。

需要装配的实体器件应尽量绑定准确封装和匹配的 3D 模型。芯片要核对引脚映射、方向及裸露焊盘，连接器和有极性器件要核对脚序。阻容默认优先用 0603 英制，也就是 1608 公制；遇到功耗、耐压或其他约束时，再按实际需要调整。缺少模型就列出具体位号，不拿错误模型补数。

图纸中的独立说明默认使用中文、EDA 默认字体和 100mil 字号，也就是 2.54mm。这个要求不改符号的位号、数值和引脚文字，也不强制把网络名翻译成中文。

## 交付时要检查什么

一次完整设计应交付可编辑原理图和必要项目库，按需要附预览与简要器件清单。报告里要说明页数和模块分配，留下关键选型依据、未验证内容，以及仍缺的封装或模型。

工具支持时，要运行 ERC 并处理实际问题；仍然存在的问题要写明原因，不能靠隐藏错误或乱加无连接标记消除报告。每页还要看实际渲染，确认文字、引脚和连接点可读。封装与模型的绑定数量及缺项也需要核对。

小范围修改就按修改范围检查，没检查过的部分不计入覆盖数量。文件保存成功，只能说明文件写好了，电路仍需要相应的电气检查和后续实物验证。
